# Performance Guide

## 목표

100~300개 이상의 아군, 적, 총알이 동시에 존재해도 플레이 가능한 상태를 유지한다. 이 프로젝트는 Ursina 기반이므로 물리 콜라이더보다 단순 엔티티, 풀링, 경량 충돌 검사를 우선한다.

## 적용된 최적화

| 영역 | 적용 방식 |
| --- | --- |
| 총알 | `BulletPool`로 재사용, 최대 크기 제한 |
| 총구 화염 | `MuzzleFlashPool`로 재사용 |
| 적 | `EnemyManager.pool`로 재사용 |
| 적 탄 | `EnemyShot` 풀로 재사용 |
| 보상 픽업 | `RewardManager` 풀로 재사용 |
| 아군 | 인덱스 구간별 update frequency 감소 |
| 충돌 | X/Z 단순 박스 판정 |
| 월드 | `SegmentManager`가 오래된 segment와 장식을 제거 |
| 파티클 | lightweight primitive + 동시 활성 수 제한 |

## 아군 최적화

`AllyManager`는 아군 수에 따라 업데이트 품질을 나눈다.

- 0~71번: 매 프레임 이동/사격 갱신
- 72~149번: 2프레임마다 간략 갱신
- 150번 이후: 4프레임마다 간략 갱신

많은 아군이 있을 때는 개별 애니메이션보다 전체 formation이 커지는 느낌을 우선한다.

## 총알 최적화

총알은 `Bullet.update(dt)`로 실제 프레임 시간을 사용한다. 범위를 벗어나면 즉시 비활성화된다. 풀 크기가 가득 차면 `max_size`까지 확장하고, 이후에는 새 총알을 만들지 않는다. 이 제한은 후반 프레임 방어용이다.

## 적 최적화

적은 렌더링 경고와 모델 로딩 비용을 줄이기 위해 기본적으로 cube/sphere primitive를 사용한다. 캐릭터 FBX는 플레이어나 보스 전용 연출로 제한하는 편이 안전하다.

## 문턱값

현재 기준 권장 상한:

- 아군: 250명 기본, 업그레이드로 증가 가능
- 총알: 260개 기본 풀, 420개 최대
- 적: 90개 기본 풀, 필요 시 확장
- 적 탄: 40개 기본, 80개 최대
- 파티클: 90개 동시 활성 제한

## 성능 문제가 생길 때 순서

1. `BulletPool.max_size`를 낮춰 총알 과밀을 막는다.
2. `AllyManager`의 고품질 업데이트 구간을 줄인다.
3. `EnemyManager.spawn_wave()`의 후반 count 증가량을 낮춘다.
4. 파티클 `max_active`와 death burst pieces를 낮춘다.
5. FBX 모델 사용 범위를 줄이고 primitive 중심으로 유지한다.

## 피해야 할 것

- 모든 아군에 콜라이더를 붙이는 방식
- 모든 총알을 새로 생성/삭제하는 방식
- 적과 총알 모두에 물리 엔진 충돌을 쓰는 방식
- 후반 웨이브에서 고해상도 모델을 다수 로드하는 방식
- HUD나 Text를 매 프레임 새로 생성하는 방식
