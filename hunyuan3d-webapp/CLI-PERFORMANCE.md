# CLI 저장·이력·ZIP 전송 성능 검증

2026-10-23 A100 서버 Linux 6.8 / Python 3.10.12에서 측정했습니다. 변경 전 소스는
Git `4f690163`이며, 같은 입력·반복 횟수로 비교했습니다. 원본 측정값과 반복값은
[benchmarks/cli-io-a100-20261023.json](benchmarks/cli-io-a100-20261023.json)에 있습니다.
GPU 추론은 실행하지 않았습니다. 아래 시간은 모델 생성 시간이 아닙니다.

| 측정 작업 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 로컬 요청 500개, 상태 조회 50회 (메시지 변경 1회) | 809.4 ms | 3.43 ms |
| 위 상태 조회의 실제 파일 읽기 / atomic replace / fsync | 25,000 / 50 / 50 | 2 / 1 / 1 |

| 서버 이력 선택, 5,000개 중 최신 50개 (1회 중앙값) | 1.480 ms | 0.0080 ms |

상태·쿠키·로컬 이력은 3회 반복의 중앙값이며 입력 생성·정확성 검증은 시간에서
제외했습니다. 상태 조회는 매번 elapsed counter가 바뀌고 실제 메시지는 한 번
바뀝니다. 변경 메시지, 원본 입력·옵션, 변경된 쿠키가 저장되는지도 확인했습니다.
파일 읽기는 실제 open 계측이며 잠금 파일 접근도 포함합니다. 로컬 이력은 양쪽에서
같은 순서의 50개 페이지와 전체 개수를 검증했습니다. 기본 페이지는 50개이며
`--limit`/`--offset`으로 이어서 조회합니다. UUID 지정은 해당 요청만 직접 조회합니다.

서버 이력은 질의별 300회 반복의 중앙값입니다. 인덱스로 작업을 선택하는 부분만
측정했으므로 JSON 직렬화·HTTP·인터넷 지연은 포함하지 않습니다. 실제 보관 작업이
적거나 네트워크 지연이 크면 전체 응답 시간의 개선은 이 배수보다 작습니다.

ZIP은 seed `20261023`의 재현 가능한 64 MiB 원본과 입력 이미지를 사용했습니다.
3회 반복했으며 warm record/archive 6회에서 ZIP 생성과 원본 바이트 재읽기가 모두
0회였습니다. 최초 캐시 생성에는 2.430초가 필요했습니다. 최초 `/record`도 ZIP
스냅샷을 만들므로 이 비용을 부담하며, 이후 다운로드와 기록 요청이 함께 재사용합니다.
캐시 무효화·용량 정리 후에도 최초 비용이 다시 발생합니다. 디스크 파일 검사와
ZIP 응답 전송은 캐시 적중 때도 필요합니다.

이어받기는 실제 loopback HTTP와 새 CLI 프로세스로 검증했습니다. 24 MiB를 재사용해
재전송량을 37.5% 줄였습니다. 전체 실행 시간은 0.700초, 재시작 실행은 0.598초였으며
앞서 받은 24 MiB의 최초 전송 시간은 재시작 시간에서 제외됩니다. 인터넷 속도의
일반적인 배수 개선을 뜻하지 않습니다. 이 테스트는 최종 파일·내부 원본 해시와 실제
서버 송신 바이트도 검사합니다. 스트림 청크는 1 MiB이며 전체 ZIP을 메모리에 올리지 않습니다.

운영 환경에서도 기존 완료 모델(581,441바이트 ZIP)로 읽기 전용 전후 측정을 했습니다.
동일 모델 ZIP HTTP 응답 중앙값은 68.57→11.00 ms, record는 7.10→6.24 ms였습니다.
141개 기록의 최신 페이지 HTTP 응답은 16.14→17.90 ms로 개선되지 않았습니다.
기존 이력 JSON 바이트는 동일하며, 이 규모에서는 전체 응답 시간 중 조회 선택 비용이
작습니다. 서버 인덱스의 이득은 기록이 늘어났을 때의 선택 비용에 한정해 해석합니다.

배포 후 실제 외부 HTTPS에서도 로그인과 doctor 준비 상태, HEAD/206/304/416 및
ETag/If-Range를 확인했습니다. 같은 기존 ZIP 전송을 131,072바이트 뒤 중단하고 새
CLI 프로세스로 나머지 450,369바이트만 받아 SHA-256과 내부 기록을 검증했습니다.
기존 141개 작업의 jobs.json 내용과 바이트 해시는 배포 전후 및 검증 전후 동일합니다.

## 재현

서버의 기존 Python 환경에서 실행합니다. `BEFORE`는 `4f690163`의
`hunyuan3d-webapp` 소스만 별도 디렉터리에 추출한 경로입니다. 운영 `.env`, 쿠키,
입력·출력 저장소를 복사하지 않습니다.

```bash
python scripts/benchmark_cli_state.py --baseline-dir "$BEFORE" --requests 500 --iterations 50 --output state.json
python scripts/benchmark_history_index.py --jobs 5000 --iterations 300 --output history.json
python scripts/benchmark_archive_cache.py --baseline "$BEFORE/generation_api.py" --size-mib 64 --iterations 3 --json-output archive.json
python scripts/validate_download_resume.py --benchmark-json download.json
```

## 검증 범위

A100에서 기존 119개 검사와 신규 상태 29개, 이력 4개, 캐시 23개, 다운로드 19개,
합계 194개를 통과했습니다. 별도 임시 작업 저장소와 fixture를 사용했습니다.
상태 갱신에는 실제 두 프로세스 저장, 외부 변경, 오래된 문서의 receipt 보존을 포함합니다.
다운로드에는 실제 TCP 중단, 강제 종료, Ctrl+C, 동시 프로세스, 변경된 ETag, 잘못된
Range, 로그인 HTML, 심볼릭 링크, 손상된 체크포인트와 ZIP을 포함합니다.
Windows에서도 상태 27개 및 다운로드 검사 실행을 확인했으며, POSIX 권한·Windows의
심볼릭 링크 생성 권한으로 제외한 항목은 A100 Linux에서 모두 검사했습니다.

[AGENTS.md](../AGENTS.md)에 기록했습니다.
