# Experimental dog-run retarget

The run clip and rig are from Petrov_the_blind's [3d dog running dog low res psx scary rigged](https://petrov-the-blind.itch.io/3d-running-dog-low-res-psx). The author identifies the source as CC0; `reference-dog-cc0.zip` is the original download. The A100-generated dog mesh and texture remain the project's existing originals; the reference dog mesh is not a runtime asset.

Blender 4.2.23: run `retarget_reference.py`, `refine_candidate.py` and `export_candidate.py` in that order with `-b -t 2 --python-exit-code 1 --python`. The first script uses `../AlleyDogRiggedEditable.blend` and the CC0 ZIP, repairs missing left-side reference weights by geometric reflection, aligns the reference rig and transfers weights to the generated dog. The second reduces joint rotation to 60%, normalizes all weights and limits them to four influences. The third exports the editor-only review candidate.

An independent rebuild completed with 251,284 weighted vertices, no unweighted vertices, weights 0.99999982–1.00000018 and at most four influences. These numerical checks do not prove quality. Four Blender CPU side-view samples showed less extreme overlap than the earlier trials but forepaws still curl unnaturally. Nine sampled frames showed vertical movement of a paw surface of about 0.134 m, so stance stability and ground contact remain unverified. The editable rig remains a source for the morph-baked game candidate, not a direct runtime skin.

`bake_morph_candidate.py` bakes 12 evaluated poses to shape keys in one mesh coordinate system. Pass `-- --lod50k` to decimate the 120,000-face candidate to 50,000 faces before baking. In the Unity editor the full candidate mesh reported 122,474,808 bytes and the 50k-face comparison 56,254,008 bytes; these are `Profiler.GetRuntimeMemorySizeLong` reports for a mesh, not GPU timing or a full memory/performance audit. Both moved skinned vertices by 0.33–0.55 m across four samples. Four Blender CPU side views retained the overall silhouette but still showed curled forepaws. Across frames 1, 6, 12 and 18, bidirectional nearest-vertex comparisons had full-to-LOD p95 approximately 2.8 mm; on a lower-leg region approximated by z < -0.25 m, p95 was 4.69–4.88 mm and maximum was 14.85–16.55 mm. Nearest-vertex distances do not establish true surface, UV or foot-contact quality. The 50k-face morph was selected for the alley encounter after the in-game comparison described below.


## Alley runtime and verification (2026-11-11)

`CandidateMorph50k.fbx`, baked from the editable 40-bone source with `bake_morph_candidate.py -- --lod50k`, is copied to `Assets/Resources/AlleyBeast/Animated/geometry.fbx`. In a quiet Unity batch session, `HappyToy.V2.Editor.AlleyBeastMorphCandidateImport.CreateProduction50k` reimports it and builds `DogMorphReview.prefab`; the source material remains `Resources/AlleyBeast/Dog.mat`. The separate original `Resources/AlleyBeast/Beast` is retained as the fallback. Unity's editor mesh measurement for the selected asset is 56,254,008 bytes (53.6 MiB), not a GPU timing, total memory, or FPS measurement.

`AlleySnapperEncounter` now starts the sampled clip only on a validated, upward-facing first impact within the marked ground area. `AlleyBeastRetreat` turns the dog toward a side refuge over 0.3 seconds, then translates at 1.2 m/s for approximately 2.25 metres. The earlier +Z direction and four-metre distance in historical recordings no longer describe the current route. The sample clock advances only when the encounter can advance, so pause holds both mesh and motion. Missing or invalid animated art selects the retained static model; if neither exists, the existing fail-open route is preserved. Ground offsets interpolate measured whole-mesh minima, not independently constrained feet. A selective 17-sample paw-surface heuristic estimated a median 10.5 mm/frame residual at 1.2 m/s (95th percentile 51 mm); it is neither proof of ground contact nor a foot-lock test. Forepaw curling, lower-limb overlap and occasional sliding remain visible, and this is not a finished high-quality quadruped gait.

Production path verification `temple-approach-visual` passed 104 EditMode and one PlayMode test. The latter uses real input, projectile collision, pickup/remainder stock, obstruction opening and travel to the temple. It checks pre-impact animation stopped, pause position/rotation/blend-shape freeze and asset-selection fallback. In a prior 24-frame Editor GPU camera sample, before the later side-refuge change, front-to-tail axes and displacement showed the animal's heading aligned with +Z after turning (dot 0.9976 or higher for frames 7–23). Full and reduced camera frames retain a comparable silhouette; the previous four-pose nearest-vertex comparison above is not a UV or foot-contact guarantee. Native player performance and GPU timing were not measured.

The high-resolution intermediate exports `Candidate.fbx` and `CandidateMorph.blend`/`.fbx` are reproducible outputs, not required inputs: `export_candidate.py` regenerates the former and `bake_morph_candidate.py` without `--lod50k` regenerates the latter from the retained editable rig. They were excluded from the source handoff to avoid duplicating large comparison artifacts.
