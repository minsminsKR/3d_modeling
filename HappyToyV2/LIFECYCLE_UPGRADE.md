# 재시작과 이벤트 중단 처리 — 2026-10-03

은밀 이동 단계 다음으로 진행·메뉴·설정·재시작 코드를 점검했다. 새로운 저장 시스템을 추가하지 않고, 확인 가능한 요청 경쟁과 중단 경로를 보강했다. 일반 입력 완주나 실제 Unity 실행 검증은 아니다.

## 확인한 결함과 수정

1. **중복 재시작과 시작 화면 요청 충돌**
   - 이전 코드는 장면 로딩이 끝나기 전에 여러 Restart 호출을 허용하고 공유 bool을 덮어썼다
   - 첫 요청만 받는 `SceneRestartGate`로 변경했다. 대상 씬과 재시작/시작 화면 의도를 함께 보관하며, 일치하는 새 씬이 한 번만 소비한다
   - 로딩 중 입력을 막고 메뉴 버튼을 비활성화한다. 이미 전달된 두 번째 콜백도 첫 목적지를 바꾸지 못한다

2. **로드 실패 이후 남는 시작 의도**
   - 이전 코드는 로딩 가능한 씬인지 확인하기 전에 공유 플래그를 설정했다
   - 저장된 현재 씬과 로딩 가능 여부를 먼저 확인한다. 동기 로드/설정 저장 실패 시 요청을 해제하고 기존 화면·입력 상태를 복원하며 오류를 안내한다
   - 정상 현재 빌드에서 이 실패를 관측했다는 뜻은 아니다. 누락/로딩 불가 씬의 실제 코드 경로와 미처리 예외를 보강한 것이다
   - 감사 실행의 자동 시작보다 명시적인 ‘시작 화면으로’ 요청을 우선한다. 도메인 재로드를 끈 Editor 실행에서도 앱 시작 시 오래된 의도를 초기화한다

3. **부모 코루틴 중단 시 남는 등장 상태**
   - 복원 시 부모 코루틴을 중단하면 Cyclopse 등장 루틴의 종료 검사에 도달하지 않아 Phase가 emerge/roar로 남을 수 있었다
   - 명시적이고 반복 호출 가능한 취소 경로로 소리·이동·배우 상태를 정리하고 resolved로 종료한다

4. **Uncat 연출의 깜빡임 완화 누락**
   - 자료실 이벤트는 기존 ReducedMotion 설정과 관계없이 조명을 변화시켰다
   - 완화 설정 시 원래 밝기를 유지하며, 완료/복원/비활성화 중단 시 조명을 복구한다. 세션 이벤트도 구독한 원래 세션에서 해제한다

5. **실제 별관 조건을 무시한 전환 검사**
   - `EventTransitionAudit`는 필수 별관 기록 없이 restore를 호출하여 실제 저장 씬에서는 복원이 거부됐다
   - 필수 기록과 복원 성공을 확인한 뒤 취소·재시작을 검사하도록 수정한다. 검사 실패를 통과로 바꾸는 우회나 장면 진행 게이트 비활성화는 하지 않는다

## 실행 검증과 남은 범위

최종 소스는 Python 검증기 24개, C# 상태 검증 143개, 정적 C# 87개·GUID 852개·감사 계약 13개 검사를 통과했다. 공식 Unity 6000.6/대응 패키지 API 참조 외부 컴파일은 런타임 62개·Editor 소스 25개와 Linux/Windows 런타임 구성 모두 오류 0개다. 레거시 API·참조·직렬화 필드 경고는 남아 있다. 최종 87개 소스 해시와 컴파일 보고서가 일치하며, 독립 소스 검토도 수행했다.

실제 공유 C# 재시작 게이트는 26개 검증을 추가했다. 중복/서로 다른 목적지 요청, 빈 대상, 다른 씬의 잘못된 소비, 한 번만 소비, 취소·재시도·새 앱 초기화를 직접 실행한다. 기존 117개와 합쳐 143개다. 이는 실제 Unity SceneManager의 실패 주입이나 장면 로딩을 실행한 것이 아니다.

`flow` 감사에는 혼합 중복 요청, 시작 화면 목적지와 낮은 자세·저주·소모품 등 새 세션 자원 초기화 확인을 추가했다. `transitions` 감사를 정식 검사 목록에 포함했다. 두 Unity 감사와 실제 조명/음향 검수는 **NOT RUN**이다. 최종 소스 검증 증거는 `Verification/quality-lifecycle/`에 기록한다.

설정 저장은 여전히 PlayerPrefs이며, 진행 저장/이어하기는 지원하지 않는다. 원본 씬·메타·빌드 선택·패키지 버전은 보존한다. 현재 기능을 출시 승인으로 취급하지 않으며, 남은 실제 차단 조건은 `RELEASE_READINESS.md`에 있다.
