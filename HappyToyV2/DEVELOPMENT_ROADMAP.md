# Happy Toy V2 — 다음 개발·개선 과제

작성일: 2026-10-06 (한국 시간)

대상 브랜치: `quality/happytoy-v2-playability-2026-10-02`

기반 커밋: `90a194f2718e5caf0c45caba51073be63adb26f2`

## 방향

학교 조사 중심에서 **소리를 듣고 길을 고르는 회랑 공포 탐색**으로 발전시킨다. 겹친 문틀·종이 격자·어둠·등불·봉인을 공간 언어로 쓰고, 경로 선택·문 닫기·은신·유한 보급이 생존에 영향을 주게 한다. 그림자복도에서 느끼는 탐색과 추적의 긴장을 참고하되 이 프로젝트의 공간·기억·추적자 정체성을 발전시킨다.

아래는 다음 작업 목록이다. 이미 구현한 기능과 검증이 아직 남은 기능을 구분하며, 미검증 항목을 완료로 취급하지 않는다.

## 현재 구현·검증된 상태

- 기본 시작을 무작위 회랑으로 변경했다. 연결된 9×9 구역에서 다섯 기억을 자유 순서로 회수하고 입구로 돌아간다. 세 층 학교는 별도 ‘폐교의 기억’ 장으로 남겼다.
- 회랑에 목재 하부판·종이 격자·겹친 문틀·봉인 제단·팔각 등불·낡은 나무 캐비닛을 적용했다. 기존 충돌체·문·기억 위치·길찾기 구조를 유지한다.
- 캐비닛 진입은 닫힘 녹음 하나, 이탈은 열림 녹음 하나만 재생한다. 옷자락·추가 금속 충격 레이어를 제거했다.
- 네 보행 추적자는 실제 신발 녹음 세 가지씩을 사용한다. 실제 타일·고인 물에서는 바닥 재질에 맞는 접촉을 선택하고, 정지·순간 이동으로 가짜 발소리를 만들지 않는다.
- 손전등과 가까운 최대 두 등불에 실제 그림자를 적용했다. URP용 해상도 설정과 학교·회랑의 안개 소유권을 정리했다.
- 두 모드의 중단 저장·기록을 분리했고, 실제 시작 버튼·Enter·일시정지·재시작·손상 저장 보존 흐름을 검증했다.
- 현재 외부 음원은 61 WAV: CC0 59개, CC BY 3.0 캐비닛 문 녹음 2개다. 출처·변환·해시·배포 크레딧을 보존했다.
- 이번 회랑 단계의 실제 Unity 검사는 **EditMode 31개 + PlayMode 17개, 최신 결과 기준 48개 모두 통과**했다. 실패 후 수정·재검증 기록도 보존한다.
- Unity `6000.6.0f1` Windows 빌드가 성공했다. `Builds/CorridorReview/quality-build.json`의 입력 파일 2,010개는 빌드 후 작업 파일 해시와 일치했다. 빌드 완료 시각은 한국 시간 2026-10-06 00:48이다.

검증 원본은 `Verification/corridor-focus/`, 이전 학교 단계는 `Verification/school-polish/`, 이전 사운드 단계는 `Verification/audio-upgrade/`에 있다. 아트 화면은 제어된 검수 장면이며 전체 생존 플레이의 증거와 구분한다. **새 Windows 회랑 빌드의 자연 시간 전체 탈출·실시간 DSP 믹스·프레임 성능 검증은 아직 실행하지 않았다.**

## P0 — 다음 플레이 배포 전에 확인할 항목

### 1. 실제 Windows 회랑 전체 경로와 실시간 오디오

- 새 빌드에서 seed 73, 211을 각각 별도 검증 폴더·프로필로 실행한다. 다섯 기억 회수와 입구 탈출까지 실제 키보드·마우스 입력 경로를 확인한다.
- `NativeCorridorPlayAudit`, `NativeCorridorInputRoute`, `RouteAudioCapture`는 구현되어 있다. 기존 오프라인 믹서 결과를 자연 시간 재생 완료로 대체하지 않는다.
- 실제 AudioListener DSP 콜백, 단계별 비무음·피크·클리핑, 일시정지 상태, PCM 전체 보존·파일 해시·저장 오류·게임/DSP/벽시계 비율을 확인한다.
- 출력 장치가 중지되어 콜백이 없으면 실패로 기록한다. 가짜 PCM, AudioRenderer 강제 렌더, `captureDeltaTime` 변경으로 통과시키지 않는다.
- **완료 기준:** 두 seed 모두 AI 억제·속도 변경·순간 이동 없이 탈출, 런타임 오류 0, 캡처 누락·비정상 값·클리핑 0, 실제 시간 관계 확인. 사용자의 저장을 건드리지 않는다.

프로젝트 루트에서 실행하는 PowerShell 예시:

```powershell
$auditOut = Join-Path (Get-Location) 'Verification/corridor-focus/native-73'
& '.\Builds\CorridorReview\HappyToyV2.exe' -v2-corridor-play-output $auditOut -v2-audit-seed 73
```

다음 실행은 출력 폴더와 seed를 211로 바꾼다. 감사 실행에 `-batchmode`를 추가하지 않는다. 결과는 `native-corridor-play.json`, 입력 경로 증거, 화면, `audio/`의 WAV 분할 파일을 함께 읽는다.

### 2. 학교 장의 실제 실행 회귀

- 같은 빌드에서 `-v2-school-play-output <절대 출력 폴더>`로 학교의 다섯 기억·계단 이동·탈출을 확인한다.
- 새 회랑의 안개·재질·그림자 설정이 학교 재시작·복원 시 남지 않는지, 층별 물방울·환경음·등장 흐름이 유지되는지 확인한다.
- **완료 기준:** 학교 전체 경로 통과, 두 모드의 기록·중단 저장 독립 유지, 제거·다시 시작 후 클립·메시·재질 누수나 중복 재생 없음.

### 3. 실제 기기 청감과 첫 플레이 검수

- 헤드폰과 일반 스피커에서 캐비닛 전환에 문 이외 효과가 섞이지 않는지 듣는다. 열림·닫힘의 길이·게인과 빠른 재조작을 확인한다.
- 몬스터 발소리의 좌우·거리·문 너머 감쇠가 실제 위치와 맞는지, 플레이어 발소리·호흡·환경음에 묻히지 않는지 확인한다.
- 처음 플레이하는 사람이 조작·다섯 기억·입구 복귀·은신 위험·유한 폭죽을 이해하는지 관찰한다.
- **완료 기준:** 청감·진행 혼란·불공정한 사망 사례를 위치와 재현 조건으로 기록하고 수정한다. 자동 테스트 통과를 공포감·청감 인증으로 표현하지 않는다.

### 4. 프레임 성능과 안정성

- RTX 2060 SUPER 환경에서 실제 해상도·그래픽 설정·동시 실행 부하를 기록하고 프레임 평균·95백분위·최악 지연을 측정한다. 다른 기기에서도 최소·권장 설정을 정한다.
- 현재 seed 73 장식은 셀별 시각 배치 453개, 등불 25개다. 가까운 그림자 두 개 제한이 실제 GPU 비용을 줄이는지 프로파일러로 확인한다.
- 필요하면 셀/재질 배칭, 그림자 거리·해상도, 먼 장식 표시를 조정한다. 보이는 벽과 실제 AI 시야를 다르게 만들지 않는다.
- **완료 기준:** 목표 기기의 60fps 예산에 맞는 설정과 병목 근거, 긴 탐색·재시작·모드 전환에서 메모리 증가 여부를 기록한다. 숨김 창 감사 결과만으로 최종 사용자 성능을 확정하지 않는다.

## P2 — 출시·운영을 위한 확장

- **그래픽·음향 설정:** 기기별 품질 프리셋, 그림자·후처리·밝기 조정과 음향 카테고리별 음량을 검토한다. 모든 설정은 실제 사용자 선택을 보존한다.
- **접근성과 입력:** 패드 전체 경로, 작은 화면·큰 글씨·울트라와이드, 포커스·키 재지정, 자막의 거리·중요도·동시 표시를 검수한다. Enter 중복 실행 방지는 유지한다.
- **탐색 기록:** 학교와 회랑의 기록을 각각 보관하면서 최근 탐색·최고 기억·탈출 시간·사용한 자원을 플레이어에게 읽기 쉽게 보여준다.
- **회랑 변주·모드:** 핵심 생존 흐름이 안정된 뒤 새로운 구역·특수 이벤트·도전 규칙을 추가한다. 변경 전후 seed별 연결성과 실제 입력 경로를 보존한다.
- **배포 자동화:** CI에서 Unity 테스트·Windows 빌드·필수 크레딧 동봉·자산 해시를 연결하고 버전이 명확한 릴리스 묶음을 만든다. 개발 빌드·감사 도구·사용자 빌드의 용도를 구분한다.
- **개발 문서 정리:** 이전 51개 음원·학교 중심 설명은 이력으로 남기고, 현재 동작·빌드·검증 결과를 README와 플레이 안내에 계속 반영한다.
