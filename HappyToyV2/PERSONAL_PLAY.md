# 개인용 플레이 개선

현재 목표는 직접 즐길 수 있는 학교 공포 게임의 재미, 조작 이해도와 분위기를
높이는 것이다. 상업 출시나 배포 심사를 전제로 하지 않는다. 기존 실행 가능한
빌드를 유지하면서 작은 플레이 개선을 검증해 나간다.

## 들리는 긴장과 여운: #14 실제 검증 완료

조용히 탐색하다 실제로 들린 적의 발소리에서 불안을 느끼고, 실제 발각 때
낮은 맥박과 공기 소리가 강해졌다가 시야를 끊은 뒤 서서히 가라앉는 음향을
추가한다. 적의 현재 Chase 상태를 벽 너머에서 읽지 않고, 실제 감각 사건만
사용한다. 보통 발소리는 낮은 긴장까지만 만들며 강한 여운은 약 5–7초에
걸쳐 사라진다. 계속 걷는 적이 이미 지난 강한 발각을 영구 유지하지 못한다.

새 음향은 방향을 알려주는 실제 적 소리를 덮지 않도록 작게 만들고, 발소리나
공격음 순간에는 새 배경층만 잠깐 낮춘다. 맥박의 빠르기는 긴장에 따라 부드럽게
변하지만 움직임·깜빡임 완화에서는 일정하게 유지하고 더 작게 재생한다.
음량 0과 일시정지를 존중하며, 기존 체력 소모로 생기는 거친 호흡과 구분한다.
새 적 위치 UI나 시각 효과는 추가하지 않는다.

소스 `c6b0c1a3`의 #14에서 기존 40개와 새 4개를 합친 **44/44 실제 Unity
검사와 Windows 빌드가 통과**했다. 7.3초 PCM의 조용한 기준/회복 완료/음량 0/
정지/결과 구간은 완전 무음이고, 발각의 여운은 줄어든다. 새 배경층 RMS는
비교 화캣 발소리의 12.7%, 동시 재생 클리핑은 0이었다. 기존 공간 음향 비교는
#13과 같다. 현재 실행본은 `HappyToyV2-Windows64-build14.zip`이며 전체를
풀고 `HappyToyV2.exe`를 실행한다. 이 분리 음향 비교와 자동 생존 경로는
새 연출의 인간 체감이나 실제 기기 성능/청취를 대신하지 않는다.

## 추격 중 막힘과 회복: #13 검증 완료

벽이나 가구에 막혀 실제로 이동하지 못해도 Shift 입력만으로 숨이 줄고,
HUD에는 달리는 중이라고 나타나던 문제를 수정했다. 입력은 이동을 요청하고,
CharacterController가 실제로 이동한 뒤 달리기 상태와 소모를 판정한다.
완전히 막혔을 때는 숨을 회복하며, 벽을 비껴 움직이거나 저주로 느려진
달리기는 기존과 같이 소모한다. 이동 속도, 초당 소모 18%/회복 12%, 탈진 뒤
25% 회복과 Shift 해제 규칙은 유지한다. 멈춘 HUD는 숨을 고른다고 안내하며
이전 발소리가 사라졌거나 안전해졌다고 단정하지 않는다.

보육실 경고 중 일시정지해 움직임·깜빡임 완화를 켜면 조명이 즉시 안정된다.
설정 화면에 머무는 동안 5초 등장 대기 시간은 흐르지 않는다.
닫힌 문을 밀어 여는 새 적 행동은 추가하지 않았다. 기존 문·은신 회복 선택을
유지하면서, 실제 이동·자원·안내가 서로 맞도록 하는 수정이다.

새 회귀는 실제 입력의 정면 막힘/대각 벽 타기/경사/저주, 여러 물리 스텝,
탈진·회복·키 해제, 보육실 설정과 반복 사망·재시작·기록·설정·시작 화면을
검사했다. 소스 `b1ca9e86`의 #13에서 기존 37개와 새 3개를 합친 **40/40
실제 Unity 검사와 Windows 빌드가 통과**했다. 원본 XML과 최종 로그의 음원
초기화 경고도 0이다. 7기록 경로는 79.440초/237.701m로 완주했고 기존 비교
음향은 #12와 같다. 현재 검증 실행본은 `HappyToyV2-Windows64-build13.zip`이며
전체 압축 해제 후 `HappyToyV2.exe`를 실행한다. 실제 기기 성능/청취와 인간의
장시간 플레이 평가는 이 자동 결과와 별개다.

## 추격자의 소리와 공간감: #12 최종 검증 완료

현재 일반 추격자들이 같은 목재 발소리와 같은 낮은 피치 공격음을 사용하는
점을 고친다. 사이클롭스·화난 화캣·언캣·베이비의 체격과 이동 방식에 맞는
짧은 접촉음을 구분하고, 등불 가면의 이동과 변신 후 마찰음을 보강한다.
공격 준비는 별도의 실제 공격 이벤트 음으로 분리한다. 가까운 적의 움직임이
빨라지면 실제 이동 거리만큼 새 접촉음의 간격도 줄어든다. 정지/워프는
접촉음을 만들지 않는다. 마네킹은 기존 관절 삐걱임의 발생 방식을 유지한다.

벽 너머에서는 낮고 둔한 소리, 실제 바닥에 막힌 다른 층에서는 더 약한
소리를 사용한다. 열린 계단은 층 높이만으로 차단하지 않는다. 마네킹의
삐걱임과 사이클롭스 등장 포효도 같은 공간 처리를 거친다. 추격 판단·속도·
공격 예고 시간과 폭죽 2개 규칙은 유지하고, 새 적 위치 HUD를 추가하지 않는다.

소스 `a7c68b1`의 #11과 초기화 후속 `f0ed7649`의 #12에서 **37/37
실제 Unity 검사와 Windows 빌드**가 통과했다. 7.26초 실제 엔진 출력의 17구간을 따로 검사했다. 벽 뒤 RMS는
열린 경로의 약 37.8%, 막힌 다른 층은 열린 수직 경로의 약 13.9%이며,
거리 밖/음량 0/일시정지 구간은 무음이었다. 같은 재생 중 소리를 재개했고
적 네 개의 동시 접촉음에서도 클리핑이 없었다. 이는 통제된 공간 fixture의
출력 수치이며, 실제 이어폰 청취나 사람의 공포감 평가와는 구별한다.

같은 실행에서 빈 음원의 자동재생 초기화 경고 40건도 발견했다. 두 생산
파일의 초기화/임시 음원 정리만 바로잡고 경고를 검출하는 회귀를 보강했다.
파형·공격 시간·추격 판단은 그대로이며, #12 재검증에서 해당 경고 0건과
포효 임시 오브젝트 제거를 확인했다. #12의 WAV와 구간 JSON은 #11과 바이트
단위로 동일하다. 최신 #12와 이전 원본 실행본/WAV를 모두 보존했다.

최신 `HappyToyV2-Windows64-build12.zip` 전체를 압축 해제한 뒤
루트 `HappyToyV2.exe`를 실행한다.

## 실제 플레이 피드백 후속: #10 실제 검증 완료

사용자가 #9를 직접 플레이하고 지적한 여섯 가지를 다음과 같이 수정했다.
아래 변경은 소스 `705c0639`의 #10 실행본에 들어 있다. 실제 Unity 검사
33/33과 Windows 빌드가 통과했고, 실제 카메라 결과를 직접 검토했다.

1. 캐비닛의 검정 장식 틈을 실제 문 두께를 관통하는 구멍으로 수정. 원래
   31개 하위 메시 이름/기준점과 충돌 상자 4개는 유지하고, 숨을 때 바깥을
   향하는 고정 눈높이를 사용한다. 웅크린 자세는 나올 때 복원한다.
2. 사이클롭스를 보이는 복도에 켜는 대신 벽 뒤의 안전한 위치를 확인하고
   실제 NavMesh를 따라 0.85m/s로 코너를 돌아 걷게 한다. 도착 후 포효하며
   플레이어 조작은 유지한다. 플레이어가 코너에 서 있으면 강제로 나타나지
   않고, 이동한 뒤 안전한 배치를 다시 확인한다.
3. 실제 시야로 발각되는 순간 짧은 노이즈와 제한된 효과음을 제공한다.
   벽/층 너머의 인식 상태를 보여주지 않고, 중복 발각은 4초간 합치며
   0.8초 후 화면을 비운다. 움직임 완화 설정에서는 움직이는 노이즈 없이
   약한 가장자리 변화와 낮은 효과음만 사용한다.
4. 음악실 피아노의 검은 건반·악보대·페달과 벤치 다리, 세 줄의 좌석/악보대,
   벽걸이 타악 교구를 보강한다. 추가 좌석 두 개와 악보대에는 기존과 같은
   충돌 및 좁은 NavMesh 장애물을 두고, 원래 통로/기록/캐비닛 접근을 검사한다.
5. 통로 위에 떠 있던 합창 판과 2층/지하/준비실 표지를 실제 벽과 액자형
   받침에 맞춘다. 원래 기록/상호작용 식별자는 유지한다.
6. 지속적인 손전등 켜짐/꺼짐 표시와 토글 자막을 없앤다. F 조작 안내,
   실제 조명 전환 및 스위치 소리는 유지한다.

장면 전체를 재생성하지 않았다. 원본 장면/메타/빌드 선택은 그대로이며
별도 백업도 보존했다. 방 배치는 이 장면만 대상으로 한 런타임 보강이고,
캐비닛 모델만 기존 제작 스크립트로 다시 내보냈다.

실제 **33개 (EditMode 6 + PlayMode 27)** 검사가 모두 통과했고 실패/건너뜀은 0이다.
캐비닛 실제 카메라 6장, 코너 등장 4장, 방 배치 5장과 발각 UI 2장을 검토했다.
새 좌석의 충돌/실제 NavMesh 조각 및 기존 접근 경로도 통과했다. 일반 입력
7기록 경로는 약 79.374초 / 237.609m로 완주했고 엄격한 엔진 믹스/일시정지
음향 검사도 유지했다. 카메라 fixture와 완주 검사는 서로 다른 사례이다.
발각 UI 그림은 세계 화면과 합성한 최종 화면이 아니며 사람의 공포감/청취를
보증하지 않는다. 자세한 원본 해시와 범위는 `CLOUD_QA.md`에 기록한다.

`HappyToyV2-Windows64-build10.zip` 전체를 압축 해제한 뒤 루트의
`HappyToyV2.exe`를 실행한다. 이전 #9 실행본도 별도로 보존한다.

## #9에 포함된 이전 변경: 폭죽과 은신 피드백

- 폭죽의 첫 폭발 프레임에 같은 소리가 두 번 재생되던 경로를 하나로 통합
- 은신 중, 재사용 준비 중, 소진, 이야기 복원 후의 Q 입력 실패 이유를 짧은
  전용 HUD에 표시. 회수한 기록/이야기 안내문은 덮어쓰지 않음
- 제목/일시정지에서는 Q가 아무 행동이나 새 피드백을 만들지 않음
- 기존 2개 수량, 물리 투척, 1.2초 도화선, 10초 연소, 추격 중 적을 유인하지
  못하는 규칙은 유지. 제목/일시정지 조작 안내에 추격 전 유인 용도를 명시
- 움직임 완화 설정은 도화선 회전과 빠른 빛 깜빡임을 억제. 일시정지 중
  설정을 바꿔도 밝은 순간이 화면에 고정되지 않게 처리
- 은신 HUD의 무조건적인 ‘기다리세요’를 중립적인 듣기/이동 안내로 변경
- 실제로 목격된 은신처의 문 앞에서 공격이 시작될 때만 짧은 경고와 별도의
  공간 문소리를 제공. 벽 너머 적의 인식 상태나 유인 성공 여부는 표시하지 않음
- 경고는 해당 은신처에서 들은 실제 공격 이벤트의 짧은 기억이며, 다른 은신처나
  재시작으로 전파하지 않음. 음량/일시정지 설정과 기존 공격 예고 시간을 유지

## 검증 범위

기존 21개 Unity 검사와 생존 경로를 유지하고 폭죽 사례 3개를 더해 총 24개를
준비했다. 캐비닛 사례에는 실제 HUD 캡처, 한 공격당 한 효과음, 일시정지와
재시작 정리를 추가했다. HUD 캡처 중에는 읽어오는 순간만 정지하고, 이후
기존 공격 시계를 다시 진행해 실제 실패/재시작 동작도 검사한다.

이 변경은 소스 `7c13e7f`의 **UBA #9에서 실제 24개 검사와 Windows 빌드를
모두 통과**했다. 원본 XML의 EditMode 6/6 + PlayMode 18/18, 실패/건너뜀 0을
확인했고, 원본 ZIP 186항목의 CRC와 새 생산 코드를 검사했다. ZIP 전체를
압축 해제한 뒤 루트의 `HappyToyV2.exe`를 실행한다. 기존 #8도 보존한다.
자동 검사가 사람의 공포감/재미를 대신하지는 않지만, 그 한계를 이유로
플레이 개선을 멈추지는 않는다. 실제 결과는 `CLOUD_QA.md`에 별도로 기록한다.

이전의 상업 배포 준비 작업은 이번 플레이 패치와 분리해 보존했다. 고지/출시
프로필/권리 확인 서류를 개인용 플레이 빌드의 선행 조건으로 요구하지 않는다.
