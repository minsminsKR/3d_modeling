기존 씬은 수정하거나 재생성하지 않았다. 저장 씬 SHA-256은 `0f2d25f211c76c7aa5299702ad15cf52d042f5a316ef32f5c4f43d69994aaede`로 기준 커밋의 LFS 객체와 동일하다. Generate/Expand 메뉴를 실행하지 말아야 한다.

## 바뀐 플레이 경험

### 1. 화면과 읽기 흐름

- 단순한 메뉴를 폐교 출석 기록 콘셉트의 타이틀·일시정지·기록·설정·결과 화면으로 정리
- 현재 목표, 별관 증거를 포함한 7단계 진행, 호흡·폭죽·은신·저주 상태를 구분
- 기록 알림과 소리 자막을 별도 영역에 표시. 공격 예고는 작은 스위치 소리에 덮이지 않음
- 전체 조사 기록을 페이지로 열람하고, 마지막 실패 상황에 맞는 생존 힌트와 탐색 시간을 제공
- 키보드 포커스와 클릭 범위 정리. 설정에서 돌아갈 목적지 보호, 창 포커스 상실 시 일시정지
- 4:3·16:9·울트라와이드에 맞춘 안전 영역을 사용. 실제 해상도별 렌더 검수는 남아 있음

### 2. 접근성·한국어

- 시야각 60–100°, 기본 72°; 감도·음량 조절 유지
- 움직임·깜빡임 완화, 소리 자막, 고대비 UI, 큰 글씨 설정을 로컬에 저장
- 완화 설정은 플레이어 카메라 흔들림·달리기 시야각 변화를 끄고, 새로 다룬 종/지하/가면 연출의 깜빡임·흔들림을 줄임. 모든 기존 모델 애니메이션까지 제거하는 기능은 아님
- 운영체제 한국어 글꼴에만 의존하지 않도록 정적 Regular 한국어 폰트를 포함. Noto Sans KR 기반, SIL OFL 1.1과 출처를 동봉
- 모든 현대 한글 음절 11,172개, 영문·숫자·UI 기호의 글리프 테이블을 검사. Unity 실제 글꼴 임포트/가독성 확인은 별도 필요

### 3. 적의 공격을 읽고 피할 수 있게

- Stalker 계열은 방출된 층을 기준으로 시야·소음 조사·경로를 판단. 다른 층 플레이어를 무조건 따라가는 추적을 막음
- 발소리 조사는 같은 층의 완전한 이동 경로와 거리 제한을 확인. 벽 너머 소리는 같은 층에서 도달 가능한 경우 계속 들을 수 있음
- Stalker는 .75초 예고와 .9초 회복을 유지하고, 예고한 방향으로 공격하므로 옆/뒤로 피할 수 있음
- 목격된 은신처 공격도 예고를 제공. 들키지 않고 숨은 상태를 임의로 발견하지 않음
- 가면의 첫 저주는 .6초, 변신 후 공격은 .75초 예고. 빗나가면 회복 시간이 생김
- 마네킹은 화면 가장자리 시선 판정과 .2초 안정 시간을 사용. .65초 공격 예고 중 돌아보거나 손전등을 끄면 취소
- 공격 시점에 거리·층·가림을 다시 검사. 일시정지에는 예고/회복 시간이 흐르지 않음
- 여러 적에게 공통 무적 시간을 주거나 무작위로 살려 주는 방식은 추가하지 않음. 각 공격이 고유한 예고/회복을 가짐
- 사망 원인·당시 목표·위치를 로그와 전체 동선 결과에 기록하여 지하 귀환 실패를 추적 가능하게 함

### 4. 손에 느껴지는 조작과 소리

- 벽 앞에서 달리기 키만 누를 때 발소리가 계속 나지 않도록 실제 이동 거리로 발소리 생성
- 마른 바닥/지하 물 발소리, 지친 호흡, 손전등 스위치, 문 걸쇠·레일, 옷자락, 기록 획득 소리 추가
- 과도하지 않은 보행 카메라 움직임과 달리기 시야각 변화. 편의 설정으로 끌 수 있음
- 작은 조사물에 좁은 조준 보조를 적용하되, 벽을 통과해 조사하지 못하게 추가 가림 검사
- 은신 전 손전등 상태를 복원하고, 캐비닛 출구가 막혔을 때 이유 안내
- 메뉴 중 상호작용 방지, 종료된 세션 정리, 중단된 등장 연출의 조명 복구 등 수명 주기 보강

모든 새 소리는 짧은 자체 합성 효과음이다. 새 음원·모델 구매나 외부 오디오 서비스 연결은 없다. 전문 녹음/청취 믹싱을 마친 음원이라는 뜻은 아니다.

## 도구·패키지 선택

기존 URP, Input System, AI Navigation, UI Toolkit을 활용했다. 패키지 버전은 바꾸지 않았다. 기능과 관계없는 플러그인을 추가하거나 Unity 버전을 올리는 대신 현재 코드의 상호작용·공격·화면·검사 기반을 고쳤다.

새 도구는 로컬 정적 검증기, 명시적으로 실행하는 Unity 검증/빌드 명령, Windows 회귀 검사 실행기다. 후속 커밋은 HappyToyV2 변경에 한정된 읽기 전용 GitHub Actions 검사를 추가한다. 정적 검사와 순수 C# 검사를 자동 실행하지만 Unity 실행 검증을 대신하지 않는다. 자동 로그인, 자격 증명 생성, 외부 서비스 업로드, 원격 푸시·배포 기능은 없다.

## 적용 및 검증

수정 파일이 있는 작업본 위에 무작정 덮어쓰지 말고 새 작업 브랜치/깨끗한 작업본에서 패치를 검사한다. 저장소 루트에서:

```sh
git apply --check happytoy-quality-upgrade.patch
git apply happytoy-quality-upgrade.patch
git lfs pull --include="HappyToyV2/Assets/Annex/SchoolAnnex.unity"
```

프로젝트 디렉터리 `HappyToyV2`에서 정적 검사:

```sh
python -m pip install -r Tools/quality/requirements.txt
python -m unittest discover -s Tools/quality -p "test_*.py" -v
python Tools/quality/validate_project.py --require-parser --output Verification/quality-static/source-validation.json
```

Unity 6000.6.0f1과 Windows 빌드 모듈이 설치·활성화된 Windows PC에서, 프로젝트를 다른 Unity 프로세스가 열고 있지 않은지 확인한 뒤 PowerShell로:

```powershell
.\Tools\quality\Run-UnityQuality.ps1 `
  -UnityEditor 'C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe' `
  -BuildPlayer `
  -Audit flow,smoke,enemy-fairness,stamina,access,cabinets,rooms,walk
```

이 실행기는 씬을 재생성하거나 저장하지 않는다. 소스/리소스 해시를 기록해 오래된 실행 파일을 현재 변경의 검사 결과로 사용하지 않도록 한다. 렌더/UI 검사가 있으므로 `-nographics`를 붙이지 않는다. 결과는 `Verification/quality-runs/`의 이번 실행 폴더에서 확인한다. 상세 검사 범위는 `Tools/quality/README.md`와 `audit_manifest.json`에 있다.
