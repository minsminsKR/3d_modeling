# Five-memory school chapter

The current user direction replaces the default flat random corridor with the preserved school's three physical floors. This is uncommitted work above `9f97bb9e51899b4a4b08aa4100cff60fc4e05146`. Git pull on 2026-10-05 confirmed that upstream branch was already current; local work was preserved.

No monster is active at chapter start. Memories are collected in order. Completing memory five leaves the threats active until the player returns to the original 1F exit. Camera and movement remain under player control during the portrait event. Pause stops reveal timers.

`MemoryChapter` configures existing actors and interactions without saving or regenerating the scene. `ChapterAtmosphere` changes runtime surface materials and adds abandoned ceiling boards, cable loops, damaged frames and graphite drawings, damp marks, wall tiles, original classroom furniture and basement hospital furniture. Physical supports and furniture have colliders and NavMesh carving. Existing stairs, water surfaces and school geometry remain intact. Local cold/warm light pools and room audio cover the three floors.

The original random corridor APIs remain available for the earlier corridor checkpoint. The title's main action starts the school chapter, and an older checkpoint is explicitly labelled as an earlier corridor. School suspension uses a separate `chapter-suspend-v1.json` slot: pause → save school → title → continue school → paused gameplay. The checkpoint preserves the five-memory sequence, elapsed play time, player pose/crouch/light/stamina/curse/noise/firecrackers, both leaves of the original doors, supplies and the state of all five original threats. Completed portrait and nursery reveals remain completed; the actors stay active on their actual school floors. Actor identities are explicit, rather than inferred from enumeration order. Starting a new school run consumes only its school slot; the earlier corridor slot remains separate.

Suspension is briefly unavailable during a reveal/transformation, an active attack, a thrown firecracker, recognition feedback or while hidden. The pause menu gives the specific reason and leaves the live paused run intact on failed writes. File writes use an exclusive lease, stale-token checks and atomic replacement; continuation consumes a successful restored snapshot once. Unknown/corrupt saves are preserved. At the title input gate, restoration first validates the schema and door movement constraints, rehydrates the saved door/obstacle states and waits two engine frames for navigation carving. It then validates player clearance and active threat navigation points before restoring memories, supplies, actors and player state. A saved player standing inside an open doorway can therefore resume there even though the fresh scene initially has closed doors. Failed restoration preserves the slot and returns to a fresh title scene. The existing corridor aggregate records remain separately labelled.

Added school persistence tests cover independent storage schemas/slots, stale and locked writes, corrupt/unknown files, real two-leaf door/player/memory/actor restoration, failed live save retries, completed original portrait/nursery restoration and a player saved inside an open door's navigation carving region. Current Unity evidence: `Verification/audio-upgrade/edit-02.xml` passed all four school slot EditMode tests; `Verification/audio-upgrade/play-03.xml` passed all five school checkpoint PlayMode tests. The initial `play-01.xml` exposed an actual support-layer mismatch (the school uses layer 0; the older corridor uses layers 8/9) and a fixture that paused during the real mannequin intro. The school-specific support check now accepts the authored physical floor layers while preserving the original corridor check, capsule clearance and NavMesh checks. The fixture waits for the original intro to finish; the in-flight reveal gate remains enforced.

## School replay records and results

The current result/record implementation adds `school-records-v1.json`, separate from both suspend slots and from `corridor-records-v1.json`. It stores total finished school attempts, escapes, highest memory stage, fastest successful escape, the eight most recently committed results and 64 bounded duplicate-run receipts. A shared exclusive lease rereads the newest totals before merging a completed result. Writes flush to a unique temporary file and atomically replace the primary with a backup. Corrupt/unknown/oversized primary files are preserved even when a readable backup is available; that backup can be previewed, but it does not justify overwriting the protected primary. A missing primary can recover its valid backup. A valid primary remains writable when only its backup is damaged: after flushing the next result under the shared lease, the unknown backup bytes are atomically renamed to a unique `.bak-preserved-<GUID>` path before creating a normal backup of the verified primary. Oversized backups are not read or deleted to perform that preservation. If archival fails, the current primary and backup stay intact and the result can be retried. Repeated Finish calls and a successful result-save retry cannot count the live run twice.

The title now shows current school totals in its school card and offers a separate recent-school-records page. The result shows memory stage, active play time, remaining firecrackers/stamina, observed controller travel, successful firecracker throws, hiding entries, player door closures, actual defeat source and the existing threat hint/current chapter objective. Actions are observed at their successful production transition: cooldown/overlap-denied throws, duplicate hiding and a rejected attempt to close a door on the player do not count. Travel uses actual controller pose changes; hide/restore teleports and menu time do not manufacture distance. These are descriptive records, not a score that penalizes hiding or rewards unsafe rushing.

New checkpoints keep the run token, action counts and observed travel as optional version-one `runProgress`. Older school saves without this field remain supported: the raw JSON codec distinguishes an absent field from explicitly malformed supplied metrics, since Unity's JsonUtility materializes missing nested classes as empty objects. Continued older saves mark action coverage as incomplete, and the result explicitly says actions/travel were observed only after continuation while the original memory stage and active time remain intact. A failed school-result write leaves the current result visible and offers an actual retry button.

The new school-record tests were added for bounded summaries, concurrent writers, retry receipts, read-only/invalid data and protected backup handling; PlayMode tests cover accepted versus denied actions, actual result/history controls and rendered large-text layouts, live write retries, new-metric suspension plus raw old-save continuation, and a complete real-input five-memory escape. Additional focused tests exercise protected-primary title/history controls, eight-report pagination through actual previous/next/back buttons at three large-text resolutions, and normal-primary/damaged-backup preservation including locked backup retries. Their latest runtime evidence belongs under `Verification/school-polish/`; earlier checkpoint/audio results alone do not certify the new result feature. `edit-02.xml` passed all 28 selected EditMode tests including missing-metrics compatibility and explicit malformed-metrics preservation. `play-01.xml` passed 19/21 tests; the two failures correctly caught clipped large-text result details/history rows/save errors. The subsequent layout changes increase actual allocated space and retain the original layout checker; current rerun evidence must be inspected before certifying those fixes.
