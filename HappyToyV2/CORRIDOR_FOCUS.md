# 돌아오지 않는 회랑 — 사용자 요청 반영

2026-10-06 기준 `90a194f2`에서 이어지는 품질 변경이다. 사용자 요청은 캐비닛 문소리에 다른 효과를 섞지 않고, 배회하는 몬스터의 발 접촉을 사실적인 녹음으로 바꾸며, 학교 중심 경험을 회랑 탐색 공포로 확실히 전환하는 것이다.

## 플레이 방향

기본 시작은 새 무작위 회랑이다. 연결된 9×9 구역과 우회 고리에서 다섯 기억을 자유 순서로 찾고 입구로 돌아온다. 유한 보급, 실제 문과 은신장, 성격이 다른 원본 추적자 네 종류가 경로 선택에 영향을 준다. 세 층 학교는 ‘폐교의 기억’ 별도 장으로 유지한다. 원본 학교 씬과 원본 캐릭터 자산을 재생성하지 않았다.

회랑의 기존 물리 구조에 목재 하부판·종이 격자·겹친 문틀·봉인 종이·팔각 등불·봉인 제단을 더했다. 불투명 장식은 실제 벽·문·제단에 붙이고 통로의 높은 천은 이동·시야를 거짓으로 막지 않는다. 중간 거리의 시야가 읽히도록 약한 거리 안개를 사용한다. 손전등과 가까운 두 등불의 실제 그림자를 허용하고, 매 프레임 모든 등불의 그림자를 계산하지 않는다.

## 사운드

캐비닛 안으로 들어가면 실제 문 닫힘 녹음 하나를, 나오면 문 열림 녹음 하나를 재생한다. 이전 옷자락·추가 금속 충격 레이어와 피치만 바꾼 동일 효과를 제거했다. 빠른 재조작은 앞 효과를 교체한다. 문 이외 환경음·플레이어 호흡·실제 적 소리는 해당 상황의 별도 음향으로 유지된다.

네 배회 추적자는 실제 신발 접촉 녹음 각 세 가지를 순환한다. 나무에서 정체성별 녹음을, 실제 타일이나 고인 물에서 그 재질의 접촉을 선택한다. 정지·순간 이동·일시정지로 가짜 발 접촉을 만들지 않는다. 떠다니는 가면의 이동은 발이 없는 정체성에 맞는 원래 이동 소리를 유지하며, 실제 공격은 이동 접촉과 분리된다.

현재 외부 카탈로그는 61 WAV(59 CC0, 캐비닛 2 CC BY 3.0)다. 캐비닛 원본은 fractilegames의 실제 캐비닛 문 녹음이며, 신발 접촉은 OwlishMedia가 공개한 녹음이다. 파일별 원본·변환·해시는 `ThirdParty/Audio/manifest.json`, 필수 크레딧은 모든 새 빌드 옆 `Audio-Credits.txt`에 제공한다.

## 검증 범위

이번 실제 원본 XML·렌더·음향·native 경로 자료는 `Verification/corridor-focus/`에 보존한다. 이전 학교 중심 53개 결과는 이전 단계 이력이다. 새 회랑 아트의 제어된 카메라, 입력으로만 이동하는 생존 경로, 오프라인 믹서, 자연 DSP 콜백과 프레임 시간은 범위를 구분한다. 실패 XML과 수정 이력을 삭제하지 않는다.

전체 프로젝트 메타 1,011개 GUID는 32 hex/중복 없이 확인했다. 잘못된 메타 때문에 누락되었던 새 테스트를 바로잡았고 실제 재실행에서 발견·통과를 확인했다. 이번 단계의 최신 고유 결과는 EditMode 31개, PlayMode 17개 모두 통과다. `play-04.xml`은 최종 회랑 아트·재질·수명, URP 그림자, 목재·타일·물의 추적자 접촉 4개 검증이 모두 통과했다. 최종 제어된 아트 화면은 `captures-04/`에 있다.

새 후보 `Builds/CorridorReview/HappyToyV2.exe`는 Unity 6000.6.0f1에서 Windows 빌드가 성공했고 입력 파일 2,010개의 현재 해시와 배포 크레딧 일치를 확인했다. 정확한 결과는 `Verification/corridor-focus/summary.json`에 기록했다. 빌드 폴더는 Git에서 제외되므로 다른 기기에서는 프로젝트를 빌드해야 한다.

새 Windows 후보의 자연 시간 전체 회랑·학교 플레이, 실시간 DSP 믹스, 실제 기기 청감·프레임 성능은 아직 검증하지 않았다. 구현된 감사 도구는 AudioRenderer 강제 렌더나 captureDeltaTime으로 시계를 바꾸지 않으며, 게임 출력만 기록하고 마이크를 녹음하지 않는다. 사용자 게임 프로필과 감사용 프로필은 분리한다. 자동 검사와 실제 입력 완주는 사람의 청감·첫 플레이 긴장·모든 랜덤 경로 난이도 판단을 대신하지 않는다. 앞으로 변경·개발할 항목과 실행 순서는 [DEVELOPMENT_ROADMAP.md](DEVELOPMENT_ROADMAP.md)를 따른다.
